# Simulation

The `simulation\` package contains the RAWES physical-world model and
the adapters used by in-process simtests and ArduPilot SITL. The
mediator is a physical-world and lockstep adapter; it does not own
flight policy, MAVLink, or production ground planning.

## Ownership and entry points

- `physics_core.py` owns the shared physics step used by
  `mediator.py` and `tests\simtests\simtest_runner.py`.
- `mediator.py` is the main full-stack bridge: decode SITL servo
  outputs, advance `PhysicsCore`, and return simulated sensor state.
- `mediator_torque.py` is the separate counter-torque/yaw-only stack
  path.
- `sensor.py`, `frames.py`, `swashplate.py`, `telemetry_columns.py`,
  and `telemetry_csv.py` are the main orientation points for sensor
  packets, frame conversions, swashplate math, and telemetry schema.
- `winch.py` and `winch_node.py` are simulation-side stand-ins for the
  ground winch and the local winch-node control loop.
- Production pumping/landing policy and MAVLink/NVF marshalling live in
  `groundstation\`, not here.

For detailed runtime ownership and module boundaries, see
[simulation internals](../design/simulation.md),
[flight-stack ownership](../design/flight_stack.md), and the
[documentation map](../README.md#documentation-map).

## Local setup and tests

Use the repository `uv` environment. Install the full simulation
dependencies with:

```
uv sync --dev --extra simulation
```

- Unit tests and Python physics simtests run on the Windows host.
- SITL stack tests run through the Docker harness.
- The generated steady-state IC is loaded through `simulation\ic.py`
  and regenerated by `tests\simtests\test_generate_ic.py::test_create_ic`.

Use the commands and selection guidance in
[testing.md](../design/testing.md) and
[sitl_testing.md](../design/sitl_testing.md).

## Logs and telemetry

Run artifacts are written below `simulation\logs\`.

- Simtests typically write `telemetry.csv` directly.
- Stack tests preserve the mediator's raw physics log
  (`telemetry.physics.csv`) plus `events.jsonl` and LinkHub artifacts.
- After the run, the harness produces the enriched `telemetry.csv` by
  sampling LinkHub observations onto the physics timeline.

Post-run diagnosis entry points live in `analysis\`.
